# 漫剧制作全流程总控 Skill

## Purpose

把四个子 Skill 串成一条可选的完整流水线：**自写小说 → 小说转剧本 → 剧本转分镜 → 三视图提示词**。既支持"一条龙"全流程产出，也支持按需路由到单个子 Skill 独立使用。

**核心原则：总控只负责"路由与排序"，不重复实现子 Skill 的细节；每个阶段都按对应子 Skill 的标准流程执行。**

## 触发与输入识别

用户提出以下任一要求即触发本总控：

1. 要求完整链路：从写小说一直做到剧本、分镜、三视图（"一条龙""全套流程""做一部漫剧"）。
2. 同时涉及多个阶段（如"写好小说后顺便转剧本出分镜""小说和它的三视图一起出"）。
3. 不确定该用哪个子 Skill，需要总控判断路由。

不触发本总控（由子 Skill 直接处理）：用户只明确要单个阶段（只要小说/只要剧本/只要分镜/只要三视图）。

输入三要素：**题材**、**字数**、**故事大纲（可选）**；后续阶段自动复用前序产出。

## 意图判断（路由）

1. **全流程**：用户要求从写小说到剧本/分镜/三视图的完整链路 → 执行全流程工作流。
2. **组合流程**：用户只要其中 2-3 步 → 按顺序执行对应子 Skill，跳过未要求的阶段。
3. **单阶段**：用户只明确要一步 → 路由到对应子 Skill，本总控不介入。

## 全流程工作流（四阶段）

每个阶段执行前，读取 `references/pipeline-map.md` 定位并 Read 对应子 Skill 的 SKILL.md，再按其标准流程执行。

### 阶段①｜自写小说（doubao-original-novel）
- 确认题材、字数、大纲（无大纲由 AI 原创设计并说明）。
- 按 doubao-original-novel 的阶段0-7执行。
- 产出：小说最终完整版全文（作为阶段②、④的输入）。

### 阶段②｜小说转剧本（doubao-novel-to-script）
- 题材与小说原文已就绪（复用阶段①产出）。
- 按 doubao-novel-to-script 的阶段0-7执行。
- 产出：完整分场剧本（作为阶段③的输入）。

### 阶段③｜剧本转分镜（doubao-script-to-storyboard）
- 确认输出格式（标准15秒版 / 豆包10秒版8-10秒）。
- 按 doubao-script-to-storyboard 的阶段0-12执行。
- 产出：完整分镜词。

### 阶段④｜三视图提示词（doubao-three-view-prompt）
- 使用小说原文（复用阶段①产出，非剧本）。
- 按 doubao-three-view-prompt 的阶段0-6执行。
- 产出：人物/兵器/神兽/法宝/道具/场景全部三视图提示词。

## 单阶段路由表

| 用户只要求 | 路由到 |
|---|---|
| 写小说 / 自写小说 | doubao-original-novel |
| 小说转剧本 / 出剧本 | doubao-novel-to-script |
| 剧本转分镜 / 出分镜词 | doubao-script-to-storyboard |
| 三视图 / 角色设定图提示词 | doubao-three-view-prompt |

组合流程按用户要求的阶段顺序依次路由执行。

## 交付契约

- 全流程按序推进，每阶段产出完整保留，并作为下一阶段输入。
- 每阶段产出的格式遵循对应子 Skill 的交付契约（小说全文/完整剧本/完整分镜词/全部三视图提示词）。
- 用户可中途指定"只做到某阶段"，即输出该阶段产物并停止。
- 用户中途修改输入（如新大纲、新原文）时，重新执行受影响阶段。
- 全流程较长时可分轮推进：先完成并交付小说，再进入下一阶段。

## 安全与边界

1. 各子 Skill 的硬约束全程生效：原创规避、剧情忠于原著、合规核查/审核、忠于原文、先等输入再输出。
2. 合规门禁在各阶段内部执行（写小说阶段3合规核查、转分镜阶段9合规审核等），任一阶段未通过不得进入下一阶段。
3. 本总控不改变各子 Skill 的任何细节规则，只做路由与排序。
4. 不向无关第三方发送用户私有稿件与个人信息。
